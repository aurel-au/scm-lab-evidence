# Session 1 Reflection

Q1 - Why is commit history useful?

Important to know who last change,when and why. Can also trace the problem for example bug appearing, so by using git log we can find the commit.

Q2 - Git vs GitHub

Git is Version control tool in our local computer. GitHub is online hosting our repositories and sharing and collab. At first i create file scm-lab-evidence as local file in my laptop, then connect to GitHub by push and clone for collaboration.

Q3 - Branch and pull request instead of editing main directly

lowering the risk of broken files. Branch can safely isolate the work editing and synchronizing teamwork by pull request so that everyone can agree or disagree with our changes.

Term		Definition
Repository	-A project containing files and folders.
Working tree	-Actual folder of files on my computer that I can see and edit.
Staging area	-Select which files to include in the next commit.
Commit		-Records the history, version, or snapshot of the files permanently.
		-Set of changes to the files and folders in project.
Branch		-Parallel version of your repository.
Merge 		-Adds the changes in your pull request and branch into the main branch.
Remote		-Version of my repository that is stored somewhere else, usually on a server like GitHub.
Push / Pull / Clone	-request shows the changes in our branch to other people and allows people to accept, reject, or suggest additional changes to your branch.
